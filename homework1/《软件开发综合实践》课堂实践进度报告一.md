## 三、自主实践说明：家乡昆明介绍页

### 选题理由

选择“家乡昆明”作为主题，因为昆明是我的出生地和成长地，我对它的气候、美食、景点都非常熟悉。昆明素有“春城”之称，四季如春，文化多元，有丰富的自然资源和人文底蕴，适合通过网页向外展示家乡的魅力。

### 页面结构说明

| 小节（标题）          | 内容类型            | 简要说明                  |
| --------------- | --------------- | --------------------- |
| h1（欢迎来到我的家乡：昆明） | 主标题             | 引出主题，点出昆明的别称“春城”      |
| 地理位置与气候         | h2 + p          | 介绍昆明的地理位置、海拔、气候特点     |
| 历史文化            | h2 + p          | 简述昆明的建城史和古滇文化         |
| 特色美食            | h2 + ul（4项）     | 列举过桥米线、汽锅鸡、烧饵块、野生菌火锅  |
| 必游景点            | h2 + ul（4项，含链接） | 滇池、石林、西山、民族村，每个景点带超链接 |
| 最佳旅行时间          | h2 + p          | 推荐3～10月及冬季观鸥          |
| 昆明风光            | h2 + img        | 展示昆明明信片级风光照片          |
| 版权/更多了解         | h2 + ul（含链接）    | 政府官网、旅游官网、百科链接，及版权声明  |

### 主题内容组织思路

我采用了“总-分-总”的结构：先用 h1 和第一段总体介绍昆明，再分“地理”“文化”“美食”“景点”等几个维度展开，最后补充“旅行建议”和“更多链接”作为实用信息。在美食和景点部分使用列表形式，让信息层次清晰。同时通过超链接引导读者进一步了解，通过图片增加视觉吸引力。

## 五、问题与解决

### 问题1：Git推送认证失败（HTTPS密码错误）

- **现象**：首次使用 `git push` 时，输入用户名和密码后提示 `remote: Invalid username or token. Password authentication is not supported for Git operations.`
- **排查过程**：查阅指南后发现，GitHub 已禁用密码认证，需使用 SSH 或 Personal Access Token。
- **解决方法**：生成 SSH 密钥（`ssh-keygen -t ed25519`），将公钥添加到 GitHub 账户，然后将远程 URL 从 `https://` 改为 `git@github.com:TWBB-hope/frontend-practice.git`，之后 `git push` 成功。
- **截图**：[此处插入截图：`ssh -T git@github.com` 成功返回 `Hi TWBB-hope!...` 的终端输出]

### 问题2：图片不显示（路径问题）

- **现象**：在 `index.html` 中写 `<img src="images/km.jpg">` 后，浏览器显示“图片损坏”图标。
- **排查过程**：
  1. 打开浏览器开发者工具 → Network 面板，看到 `km.jpg` 状态码为 404。
  2. 检查文件路径：`theme-page/images/km.jpg` 确实存在。
  3. 发现文件名大小写不一致：HTML 中写的是 `km.jpg`，但实际文件名是 `Kunming.jpg`。
- **解决方法**：统一文件名为小写 `km.jpg`，刷新后图片正常显示。

## 八、独立研究任务记录（选做）

### 研究任务1：.gitignore

#### 1.1 作用理解

`.gitignore` 用于告诉 Git 哪些文件（如系统自动生成文件、编辑器配置、日志、敏感环境变量等）不需要纳入版本控制，保持仓库干净且避免敏感信息泄露。

#### 1.2 编写的 `.gitignore` 文件内容

```gitignore
# macOS 系统文件
.DS_Store
.AppleDouble
.LSOverride
._*

# Windows 系统文件
Thumbs.db
ehthumbs.db
Desktop.ini

# 编辑器临时文件（VS Code / Vim / Sublime）
.vscode/
.idea/
*.swp
*.swo
*~

# 日志文件
*.log
npm-debug.log*
yarn-debug.log*
yarn-error.log*

# 环境变量文件
.env
.env.local
.env.*.local
```

#### 1.3 每条规则的解释

| 规则                          | 解释                                   |
| --------------------------- | ------------------------------------ |
| `.DS_Store`                 | macOS 在每个文件夹生成的图标位置和显示选项缓存文件，对项目无用   |
| `.AppleDouble` / `._*`      | macOS 用于存储文件扩展属性的隐藏文件                |
| `Thumbs.db` / `Desktop.ini` | Windows 的缩略图缓存和文件夹自定义配置，无用且可能暴露目录结构  |
| `.vscode/` / `.idea/`       | 不同 IDE 的用户个人配置，各开发者习惯不同，不应强制统一       |
| `*.swp` / `*.swo` / `*~`    | Vim/Emacs 等编辑器的临时交换文件，崩溃恢复用，正常开发时可忽略 |
| `*.log` / `npm-debug.log*`  | 日志文件，会不断增长，且通过程序可重新生成，无需提交           |
| `.env` / `.env.local`       | 环境变量文件常包含密钥、数据库密码，坚决不可提交             |

### 研究任务3：字符编码与 HTML 实体

#### 3.1 删除 meta charset 后的乱码现象

**实验步骤**：

1. 复制 `theme-page/index.html` 为 `index-test.html`
2. 删除 `<head>` 中的 `<meta charset="UTF-8">`
3. 用浏览器打开，中文字符变为乱码（如“昆明”显示为“æ˜†æ˜Ž”）
4. 恢复 `meta charset` 后刷新，中文恢复正常

**截图对比**：

- [此处插入截图1：删除 `meta charset` 后页面中文乱码的效果]
- [此处插入截图2：恢复 `meta charset="UTF-8"` 后中文正常显示的效果]

**结论**：`<meta charset="UTF-8">` 是中文页面必不可少的声明，浏览器根据该声明正确解码字符，否则会采用错误编码导致乱码。

#### 3.2 常用 HTML 实体的使用

| 实体写法     | 显示效果    | 说明                 |
| -------- | ------- | ------------------ |
| `&copy;` | ©       | 版权符号               |
| `&nbsp;` | （不换行空格） | 单词间的空白，不换行         |
| `&lt;`   | <       | 小于号，用于显示 HTML 标签本身 |
| `&amp;`  | &       | 和号（&），用于显示 & 字符本身  |
